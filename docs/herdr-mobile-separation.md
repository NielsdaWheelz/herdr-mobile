# herdr-mobile and skidbladnir separation

2026-09-25. implementation plan from the owner's requested product split.
this document changes scope and acceptance; this repo's source implementation
and immutable `v0.9.0` release are complete. github names have transferred;
coordinated fleet and phone cutover remains pending. the
[deployment contract](dev-server-handoff.md) records implementation evidence
and the published pin. the [original-repo handoff](skidbladnir-restoration-handoff.md) and
[dev-server handoff](dev-server-separation-handoff.md) are self-contained agent
assignments derived from this shared contract.
[delivery tracking](issues/herdr-mobile-separation.md) owns remaining work.

## 1. outcome and boundaries

rename this herdr-backed repository to `NielsdaWheelz/herdr-mobile`.
rename the preserved `NielsdaWheelz/skid-v1` repository to
`NielsdaWheelz/skidbladnir`. both products run concurrently on macbook, devbox,
arch, and the same android phone.

the invariant: installing, pairing, launching, updating, restarting, rolling
back, or removing either product does not change the other's owned files,
credentials, services, workers, ingress, or phone data. neither repository
builds, downloads releases from, or executes the other product.

the owner permits all existing herdr panes to die. preserve no old pane
metadata, terminal references, or live attachments; add no migration reader or
compatibility alias. new herdr-mobile pairings and host credentials are fresh.
original skid also gets fresh gateway credentials when it reclaims its paths.
the phone cutover explicitly resets obsolete pairings in the old package.

upstream herdr keeps its binary, service, socket, and runtime identity.
herdr-mobile remains only its phone app and gateway: no skid cli, hook runtime,
provider history, notifier, or second terminal supervisor returns here.
original skid retains its tmux architecture and its own required integrations.

the products may share host-managed tailscale, provider executables, operating
system tools, and user-selected working directories. provider/tool upgrades are
separate deployment operations, not side effects of gateway updates or removal.
this is operational independence under one uid, not containment of hostile
processes or concurrent edits to the same user project.

source traps established by inspection:

- android's `MachineOrigin` requires and reconstructs port `8443`;
  `scripts/fleet` also hardcodes it. changing a service flag alone cannot work.
- dev-server's linux installer refuses a gateway port other than `7341`.
  its pins, launchers, services, retention, receipts, and rollback share the
  skid namespace. its ansible role removes `/usr/local/libexec/skidbladnir`.
- `scripts/install-android` admits only `dev.niels.skidbladnir` and installs
  with `-r`. update its package and signer checks with the new app.
- the launcher ship and kotlin package references are generated by
  `scripts/gen-ornament`; xterm names and hashes are owned by
  `android/terminal.lock`. change their owners, then regenerate.
- original skid requires `nativeControlPath` and its retired native provider
  helper. restoring its source alone does not restore a working deployment.
- account wrappers can override an explicitly selected provider home; provider
  hooks can also load through project configuration. section 5 owns isolation.
- jarvis calls herdr directly, but its profile-to-home mapping and the ssh
  gate's environment allowlist must agree with any provider-home changes.

## 5. provider and runtime separation

provider home selection is an installation contract shared by the host
configuration, shell command resolution, integration installer, and jarvis's
gate. a private gateway directory alone does not establish it.

move herdr's interactive provider configuration into
`~/.local/share/herdr/providers/`, with five explicit homes: `codex-personal`,
`codex-work`, `codex-work2`, `claude-personal`, and `claude-work`. the phone
still offers its existing four profiles; personal claude remains the native
herdr/jarvis default, with an explicit private home. herdr's upstream binary
and native integration installer own this configuration; herdr-mobile gains
no hook implementation.

original skid gets fresh homes under
`~/.local/share/skidbladnir/providers/`: `codex-personal`, `codex-work`,
`codex-work2`, `claude-personal`, and `claude-work`. personal claude is a shell
default, not an added forge profile. no symlinks or shared mutable credential,
history, plugin, hook, cache, socket, or discovery files between product homes.
authenticate and trust integrations through the providers' normal setup.
do not copy whole existing account homes; devbox's existing homes also contain
jarvis discovery state. fresh setup is required on each host for the profiles
used there; record missing login/trust as a prerequisite, not a passing launch.

update herdr-mobile's host profiles, jarvis's worker profile/default mapping,
the herdr gate's explicit environment allowlist, desktop command defaults,
instruction provisioning, and herdr integration targets together. command
resolution inside herdr must select the new default homes and preserve the
pane's explicit profile environment and existing permission policy. account
wrappers must select the corresponding new interactive home. keep jarvis's
separate cognition services, account-home declaration, discovery sockets,
history, and credentials at their existing locations; do not move cognition
because its home declaration currently also feeds interactive wrappers.

remove only verified product-owned integration entries and scripts from the
ordinary `~/.codex*` and `~/.claude*` homes once the new setup is ready.
preserve unrelated settings, user hooks, credentials, and cognition discovery.
no recurring product installer writes those ordinary homes or project hook
files. shared user-selected project settings remain user-owned inputs.

original profile rows must use absolute native provider executables and their
explicit environment/arguments, or a skid-owned wrapper only where necessary.
the shared `codex-work`, `codex-work2`, and `claude-work` wrappers force the old
homes and cannot implement this contract. preserve the legacy explicit claude
identity plugin and verify its loaded origin. provider configuration and
helper discovery must resolve the same claude home.

apply that ownership to manually started agents too. every newly created skid
shell must resolve bare `codex`/`claude` and account-specific commands to skid
homes, including after login-shell startup; every herdr shell resolves them
to herdr homes. establish product-scoped shell defaults and, where required,
simple product-scoped wrappers with native executable targets. explicitly
selected profile homes take precedence. a shared account wrapper that forces
the other product's home fails this contract even when forge launches work.
do not rewrite the environment of existing user tmux sessions or install a
general runtime-selection framework.

restore original skid's native helper as a separately pinned skid dependency.
historical evidence identifies `llm-calling` at
`ec97adeb9ddd0f91b141f89cc42cff7cc7efdb8f`, uv `0.11.28`, python `3.12.13`,
and claude sdk `0.2.130`; these are investigation inputs, not proof of current
compatibility. the original agent must inspect the exact helper boundary and
qualify it with current provider binaries. prefer a skid-owned helper command
such as `skidbladnir-provider-runtime-control`. do not restore an old whole
dev-server revision, which would reclaim shared hooks and wrappers.

scrub foreign runtime context at process creation, including `HERDR_*` from
skid's gateway, tmux startup, and provider launches, and tmux context from the
herdr server. inspect existing tmux server environment without changing it;
do not mutate unrelated existing tmux sessions to make a test pass. test
launches from a shell inside the opposite runtime as well as ordinary shells.
native hook guards remain intact; add no general hook dispatcher.

project settings are also configuration inputs. test `cwd=$HOME` and a real
shared project: codex can discover `$HOME/.codex/hooks.json` as project config
when another `CODEX_HOME` is selected. this is why both products get homes
outside those ordinary project-config locations. audit inline and plugin hook
sources too. section 7 cannot pass on environment guards alone if the other
product's hook or trust changes still affect startup. record any genuine
provider limitation in the tracking issue.

## 6. ordered delivery and rollback

### a. prepare source and immutable inputs

implement and review the app changes and dev-server separation before changing
live ownership. record exact repository ids and heads, signer pins, old
artifact digests, service definitions, and owned paths. keep credentials and
provider data out of evidence. privately retain the known old gateway/apk
artifacts needed during the short transition; do not depend on a redirect.

prepare two independently selectable dev-server operations. applying either
product must not validate the other's pin, credentials, signer, provider homes,
or installed state. retain shared host-tool provisioning as a separate owner.
split global pruning/cleanup and receipt handling accordingly; audit ansible,
platform scripts, and protected-path checks as well as `lib/skidbladnir.sh`.
remove the old unconditional skid-removal operations before original skid
returns. serve changes target only the exact owned port and handler; no reset.

### b. transfer github names

one operator performs the sequence; both repo agents stop publication while
names are in transition.

name reclamation was not initially proven. github documents permanent namespace
retirement for sufficiently used repositories; the detailed transfer/account
rename rules do not conclusively settle this same-owner repository rename.
the observed clone volume was treated as a preflight uncertainty, not a
promise of availability. the same-owner swap succeeded on 2026-09-25; both
repository ids were checked afterward. the fallback below remains the rule
for any refused future rename. if
github refuses reclamation, preserve both repositories and their histories,
leave the original at `skid-v1`, and record the unmet naming requirement for
resolution with the owner/github. do not delete/recreate repositories, replace
their histories, or silently change their identities as a workaround.

1. verify id `1342599607` is the current herdr-backed repo and the target name
   is available. rename it to `herdr-mobile`.
2. retarget every known clone/worktree remote, checkout path reference,
   deployment download URL, release command, and current/historical source
   link for that repo to `herdr-mobile`. inspect linked worktrees before moving
   local directories. update old-release download URLs without changing bytes
   or digests. stage the new deployment pins when the new release exists.
3. prove the herdr-backed repo's fetch/push and artifact consumers use its new
   canonical name. then rename repository id `1386409483` from `skid-v1` to
   `skidbladnir`; update its remotes. confirm both ids resolve under the intended
   final names. never replace a remote based on basename alone.
4. enable original skid's required immutable-release setting and verify its
   hosted checks. it has no copied release assets: publish a new release from
   its own checked source. do not republish the herdr-backed `v0.8.0` as skid.

github's old-name redirect stops working when the name is reclaimed. a stale
herdr clone would then address original skid. the repository-id check is a
cutover check, not a new permanent identity framework.

use a new increasing release for each product; `v0.9.0` is the planned first
separated release if still unused. original skid must have android version
code greater than the observed `8000` (the existing encoding makes `0.9.0`
equal `9000`). the two repos may use the same version string independently.
recheck tags and installed version immediately before release/install.

### c. establish herdr-mobile, then release the skid namespace

on each host, first recheck port availability and tailnet policy for `8444`.
provision herdr-mobile's fresh handle/bearer, config, service, pin, and ingress.
prepare a private fleet operator config containing only its three gateways.
its installation never reads old skid credentials as defaults.

run the cutover controller outside the herdr panes being discarded.
coordinate with jarvis before resetting herdr: stop new worker dispatch and
settle or explicitly fail pending work under jarvis's existing cutover rules.
the owner waived pane survival, not truthful action accounting. stop the old
phone gateway, close/reset only the intended herdr runtime, and discard its
old session snapshot through the supported stopped-runtime path. a restart
alone may restore shells from `~/.config/herdr/session.json`; confirm old panes
and metadata are absent before reopening launches. retain herdr's config,
binary, socket identity, and jarvis gate. restart and verify the runtime, then
the new gateway. no global process-name kill.

after herdr-mobile works on all three hosts, install and pair its new phone
app. only then decommission the former herdr-backed skid gateway services,
launchers, ingress, and activation receipts. retire their old bearer/handle
and private fleet config. explicitly inventory and remove or privately
quarantine obsolete release/unit generations so the restored skid installer
cannot select the herdr-backed `v0.8.0` as its previous generation.
preserve the original android signing key and unrelated user files in the
old config directory; never recursively delete it.

the operator now declares the skid namespace handed back. original skid may
install its own fresh credentials, tmux-era config/helper, independent service,
and `8443` ingress. re-pair its app only to those new credentials.

before this handback, recovery can temporarily restore the saved old gateway
in its old namespace. after handback, never roll herdr-mobile back into skid
paths, ports, or package id. stop/repair it within `herdr-mobile`, or use a
previous separated release when available. original skid has its own rollback
chain; neither chain includes the other's artifacts. recovery need not restore
discarded herdr panes.

### d. replace the old phone package

install signed `dev.niels.herdr.mobile` alongside the existing package, with
its new signer, distinct icon, and fresh pairings. prove it works before
changing the old package. both apps retain disabled backup/device transfer;

when all original gateways are ready, force-stop only

the reset loses its old pairing and presentation preferences; it never clears
herdr's new package. use explicit package/serial targeting. no downgrade flag,
global app reset, or reliance on compatible private preference schemas.

## 7. acceptance

run each repo's engineering checks and release-integrity checks. use temporary
integration/live probes, reviewed and removed before commit, under the
[testing policy](rules/testing.md). engineering checks alone prove no behavior.
phone/tmux work must satisfy the applicable current-turn authorization rules;
this planning turn's usb approval is not a standing test authorization.
unexecuted boundaries are `NOT_RUN`.

| boundary | required evidence |
| --- | --- |
| repositories and releases | final names resolve to intended ids; clean independent builds and hosted checks; each release/pin/installer uses only its own source, assets, signer, and package |
| both gateways, each host | both services and serve handlers active concurrently; distinct handles/bearers; wrong-product invite, auth header, and credential rejected before mutation |
| runtime isolation, each host | exercise all four forge profiles plus manually typed bare/account provider commands in new shell terminals; correct private homes, integration targets, and runtime context; codex and claude run concurrently in both products; repeat from `$HOME` and a shared project; neither product observes or controls the other's worker |
| ownership lifecycle | while one product has a live worker and phone attachment, restart/reinstall the other gateway and exercise its rollback; worker and attachment remain usable and unrelated owned files/ingress remain unchanged; repeat in reverse |
| removal | each scoped removal preserves the other product's credentials, service, runtime, ingress and provider homes; exercise on disposable installations before live fleet use |
| phone | both signed packages, labels and distinct icons present; independent pairing to all three hosts, inventory, launch, attach/input/detach, interrupt/stop; restarting/updating one app preserves the other's data and use |
| jarvis | unchanged herdr targeting semantics and working codex/claude launch after profile-home/gate updates; cognition services, account-home declarations, discovery, credentials, and unrelated settings unchanged; only inventoried old integration entries/scripts removed; no pending action replay across the reset |
| repeat apply | neither product's ordinary apply reclaims or deletes the other's namespace; gateway apply remains possible with the other's installation absent |

only test-created tmux resources on an isolated `-L` socket may be killed,
resized, or retargeted. if legacy tooling cannot target that socket, resolve
the temporary probe method before running it; do not turn the user's default

record source/artifact identity, platform, typed result, and any blocker.
